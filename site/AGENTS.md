# Agent Instructions

## Commands

| Task | Command |
|------|---------|
| Dev server | `npm run site:dev` |
| Build (regenerates stats, copies docs assets) | `npm run site:build` |
| Regenerate TUI captures (live sessions, both themes, ~cents) | `npm run -w site capture` |
| Regenerate repo stats only | `node site/scripts/repo-stats.mjs` |
| Screenshot audit set (both themes × 5 widths) | `node scripts/shots.mjs <outDir> [urls...]` (site workspace; needs `npm run preview -w site` on a port, uses system chromium via `CHROME_BIN`) |
| Preview built site | `npm run preview -w site` |

## Layout

| Area | Purpose | Entry point |
|------|---------|-------------|
| `site/src/pages/` | Routes; the landing owns its own `<head>` (canonical link), others use `layouts/` | `src/pages/index.astro` |
| `site/src/components/` | Page blocks: `TuiCapture`, `CodeBlock`, `FactsStrip`, `RepoCard`, `CommitGraph`, `Faq`, `Section` (which takes a mono `label`, not a number: sections are an argument, not a sequence) | `src/components/TuiCapture.astro` |
| `site/src/lib/ansi.mjs` | SGR parser turning captures into styled runs (tested by root `tests/site-ansi.test.mjs`) | `src/lib/ansi.mjs` |
| `site/src/tui/` | Committed `.ans` captures under `<theme>/` (dark, light) + `captures.json`; regenerated by `scripts/capture-tui.mjs` | `src/tui/` |
| `site/src/stats/` | Generated `repo.json` (counts, contributors, per-day commits, languages); regenerated by `scripts/repo-stats.mjs` in prebuild and predev, not tracked | `src/stats/repo.json` |
| `site/public/` | Static assets; `docs/efficiency*` copied from the repo root by prebuild | `public/` |

## Conventions

- `src/tui/<theme>/*.ans` (one set per engine theme, dark and light) and `src/tui/captures.json` are generated: never hand-edit; the landing's numbers must stay machine-derived (`AGENTS.md` root rule, enforced here by the two scripts). `src/stats/repo.json` is likewise generated and untracked; prebuild and predev recreate it.
- `capture-tui.mjs` redacts the operator's home and repo paths before writing captures; keep the redaction intact when touching the script (history has been rewritten once to purge a leak).
- `capture-tui.mjs` boots the real engine and captures each theme in its own pass (the theme flips by rewriting the agent settings' theme key, saved and restored around the run, plus `/reload`): needs repo-root `npm install`, provider credentials, and tmux; costs a few cents; `TORUS_DREAMING=0` keeps scenes deterministic.
- Driving the TUI via tmux: keys must be `M-t`/`M-1`, never `Alt+t`/`Alt+1` (tmux types the latter literally into the chat editor).
- Terminal figures on the landing are captures of real sessions, not mockups: every scene ships as a dark and a light capture, and the figure shows the variant matching the site theme; keep it that way when editing copy or components.
- A change that reshapes a captured surface (statusline, fleet browser, editor chrome, theme palette) re-runs `npm run -w site capture` in the same PR and commits both variants; a stale capture is a lying screenshot.
Dark is the site's default theme; light is reached only through the visitor's pin (`html[data-theme="light"]`), and there is no `prefers-color-scheme` branch: do not reintroduce one. Terminal objects (captures, fences, code blocks) follow the active theme, and the `--term-*` values mirror the committed captures' palettes per variant.
- The site speaks the TUI's own visual language: mono is the machine voice (wordmark, section labels, stats, commands, captures), sans the explainer's; accent hues and each theme's ground come from the committed captures' palettes. Captures render with terminal semantics: square frames, no window chrome, lines never wrap (overflow scrolls horizontally under a themed scrollbar), and the head row carries the geometry from `captures.json`.
- The landing's engine-pin line reads `package.json` `devDependencies` at build time and fails the build if the pin is missing; version strings on pages are never retyped by hand.
- The pages workflow deploys `site/dist` on every main push and checks out with `fetch-depth: 0` because the build derives stats from git history (`.github/workflows/pages.yml`).
- Preview must honor the `/torus` base (`npm run preview -w site`, or `npx astro preview`): serving `dist/` at a host root 404s every `/torus/_astro/...` asset, and screenshot or DOM checks against it audit an unstyled page. `astro preview` binds IPv6 loopback (`localhost`, not `127.0.0.1`).
- Root biome covers `site/src` and `site/scripts` (tabs, double quotes); root `tsc` does not type the site.
