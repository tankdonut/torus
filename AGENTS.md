| Task | Command |
| ------ | --------- |
| Test one file | `node --experimental-strip-types --import ./tests/resolve-ts-hook.mjs --test tests/hashline.test.mjs` |
| Test all | `npm test` |
| Build the site | `npm run site:build` |
| Typecheck | `npm run typecheck` |
| Lint/format one file | `npx biome check extensions/hashline/index.ts` |
| Lint all | `npm run lint` (biome + markdownlint) |
| Auto-fix lint+format | `npm run lint:fix` |
| Full gate | `./make.sh check` (typecheck + lint + test + smoke) |
| Build binary | `./make.sh build` |
| Build container image | `./make.sh image` |
| Test container image | `./make.sh image-test` |
| Overhead bench (spawns engine, costs tokens) | `npm run bench:overhead` |
| Startup bench (spawns engines, no tokens) | `npm run bench:startup` |
| Per-turn FS microbench (no engine spawn) | `npm run bench:fs` |

## Conventions

- Quality gates: Biome lint/format (`biome.json`) + strict `tsc --noEmit` + `node:test`, enforced by husky pre-commit (typecheck + lint + test); CI (`.github/workflows/ci.yml`) runs lint + typecheck + smoke.
- Bracket member access (`process.env["X"]`) is the repo convention (`useLiteralKeys` is off in `biome.json`); regexes matching ANSI/OSC control sequences are intentional (`noControlCharactersInRegex` off).
- TypeScript is type-stripped at runtime (`--experimental-strip-types`), never compiled; `tsconfig.json` is `noEmit`; keep imports runtime-resolvable ESM.
- A new extension loads only after it is added to the `pi.extensions` array in `package.json`.
- A change that adds, renames, or removes a config section, knob, or `TORUS_*` env read ships with its `docs/configuration.md` coverage in the same PR; `tests/docs-coverage.test.mjs` enforces presence of every registered section and knob there.
- `dist/` is wiped and regenerated by `scripts/build-binary.sh`: never hand-edit.
- `.npmrc` is agent-blocked by `cc-safety-net` by design; humans create it via `./make.sh npmrc`.
- Guarded writes and reads: bare `cat`/`head`/`tail` of an absolute path is blocked: use the read tool; overwriting an existing similar file via `write` is blocked: use `edit` (`extensions/guards/index.ts`).
- The engine is pinned in `package.json` (`@earendil-works/pi-coding-agent`); `TORUS_PI_BIN` overrides the binary path.
- Repo docs (README, CONTRIBUTING, docs/) make no hand-written numerical claims that duplicate a machine source of truth: tool/skill/agent counts, version floors, model context sizes. They go stale silently; reference the authoritative file (`package.json`, `agents/`, `docs/extensions.md`) instead. Benchmark numbers pasted into `docs/efficiency.md` are the machine's report and stay exempt from this rule; the file itself is hand-maintained and follows `docs/style.md` like any other page. Truly regenerated output (`docs/efficiency.html`, `docs/bench-records.json`, `CHANGELOG.md`) is never hand-edited.
- Changes that can shift delegation overhead (child system prompts, the canonical extension set, anything that grows what a spawned engine loads) carry a before/after comparison in the PR using the matching instrument: `npm run bench:overhead` for token/cost, `npm run bench:startup` for cold-start wall time, `npm run bench:fs` for per-turn filesystem ops (`scripts/bench/`); the overhead bench's run history lives in `docs/bench-records.json`.

## Commit convention

Commit subjects are release-mechanical: release-please maps them to version bumps and changelog entries. `feat:` lands under Features and bumps the minor, `fix:` lands under Bug Fixes and bumps the patch, `!` or a `BREAKING CHANGE:` footer is breaking (minor while 0.x via `bump-minor-pre-major`, major after 1.0), and `chore:`, `ci:`, `docs:`, `test:` bump nothing. Subjects may carry a Conventional Commits scope after the type, e.g. `feat(extensions/hashline):` or `fix(agents):`; the full subject-to-effect table is in [docs/release-workflow.md](docs/release-workflow.md).

- Scopes never change the bump: `feat(extensions/hashline):` bumps exactly like `feat:`. Use `area/name` when the change stays inside one item of an area (`fix(extensions/hashline):`, `feat(agents/leader):`), the bare area when it spans the area (`fix(agents):`, `chore(tests):`), and no scope for cross-cutting changes. Scope names copy the repo's directory segments (`extensions`, `agents`, `skills`, `tests`, `runtime`, `scripts`, `docs`) so each area keeps one spelling; `deps` is reserved for dependency bumps (engine pins land as `feat(deps):`, below).

- Docs follow `docs/style.md`; `tests/docs-style.test.mjs` enforces its mechanical rules (banned filler, prose em dashes, retired keywords, link resolution, README quickstart ordering) and markdownlint enforces the structural ones via `npm run lint`. Dispatches for prose work pass the `technical-writing` skill. Exemptions: `CHANGELOG.md` (release-please output) and non-markdown regenerated artifacts (`docs/efficiency.html`, `docs/bench-records.json`). `docs/efficiency.md` is hand-maintained and fully in purview; only its pasted bench numbers are exempt from the no-hand-written-numbers rule.
- Engine-pin bumps (`@earendil-works/pi-*` in `package.json`) land as `feat(deps):` (every shipped binary carries the pin, so they are user-visible). Renovate applies this automatically (`renovate.json` `packageRules`); hand-bumped pins keep the same subject. Engine-pin bumps also require the release-workflow env-audit step before merge: re-run `tests/env-hygiene.test.mjs` and re-verify the engine's `.env` autoload behavior (`docs/release-workflow.md`).
- Squash-merges keep the PR title verbatim as the commit subject; get the subject right at merge time.
- No plan coordinates (wave/task numbers, plan slugs, ledger paths) in commit messages or code comments; history reads as the repo's own work.
